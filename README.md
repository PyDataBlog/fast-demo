# Fast Demo API

This project is a FastAPI application. This guide explains how to run it using Kubernetes (with k3d and Nginx Ingress) or Docker directly.

## Using the Makefile

A `Makefile` is provided to simplify common tasks. Run `make help` to see available targets and options.
You will need to have `make` installed on your system.

Key variables for the Makefile:

- `K8S_INGRESS_IP`: Your desired Ingress IP for Kubernetes (e.g., `192.168.86.160`). This **must** be provided for Kubernetes deployment targets. Example: `make k8s-deploy K8S_INGRESS_IP=your.ip.address`.
- `K8S_CLUSTER_NAME`: Name for the k3d cluster (default: `mycluster`).
- `DOCKER_IMAGE_NAME`: Docker image name (default: `fast-demo`).
- `DOCKER_IMAGE_TAG`: Docker image tag (default: `latest`).

## Running with Kubernetes (k3d)

This section describes how to run the application on a local k3d Kubernetes cluster using Nginx Ingress, managed by the `Makefile`.

### Prerequisites

- Docker installed on your system.
- k3d installed (see [k3d installation guide](https://k3d.io/#installation)).
- kubectl installed (see [kubectl installation guide](https://kubernetes.io/docs/tasks/tools/install-kubectl/)).
- Helm installed (see [Helm installation guide](https://helm.sh/docs/intro/install/)).
- Make installed.

### Setup and Deployment

1.  **Create k3d Cluster (if you don't have one):**
    This command creates a k3d cluster suitable for Nginx Ingress.

    ```bash
    make k3d-cluster-create
    ```

    _(You can customize the cluster name: `make k3d-cluster-create K8S_CLUSTER_NAME=anothercluster`)_

2.  **Install Nginx Ingress Controller (if not already installed in your cluster):**
    This installs Nginx Ingress into the `ingress-nginx` namespace.

    ```bash
    make install-nginx
    ```

3.  **Build, Import, and Deploy the Application:**
    This sequence of commands builds the Docker image, imports it into your k3d cluster, prepares the Kubernetes manifest with your IP, and deploys the application.
    **You must provide your `K8S_INGRESS_IP` here.**

    ```bash
    make all-k8s K8S_INGRESS_IP=<your.actual.ip.address>
    ```

    For example:

    ```bash
    make all-k8s K8S_INGRESS_IP=192.168.86.160
    ```

    Individual steps if preferred:

    ```bash
    # Build the Docker image
    make docker-build

    # Import the image into k3d
    make k3d-image-import # (ensure K8S_CLUSTER_NAME is correct if not default)

    # Deploy to Kubernetes (this will also prepare the manifest)
    make k8s-deploy K8S_INGRESS_IP=<your.actual.ip.address>
    ```

    You can monitor the pod status with `kubectl get pods -n demo -w`.

### Accessing the Application (on k3d)

Once deployed, use the `k8s-access` target to see the application URLs. You must provide the same `K8S_INGRESS_IP` you used for deployment.

```bash
make k8s-access K8S_INGRESS_IP=<your.actual.ip.address>
```

This will output URLs similar to (replace `<your.actual.ip.address>` with your IP):

- **Main API Root**: `http://<your.actual.ip.address>.nip.io/api/`
- **Main API Items (POST)**: `http://<your.actual.ip.address>.nip.io/api/items/`
- **Sub API v21 Index**: `http://<your.actual.ip.address>.nip.io/api/v21/`
- **Sub API v21 Sub-route**: `http://<your.actual.ip.address>.nip.io/api/v21/sub`

Example using curl (replace IP accordingly):

```bash
curl http://<your.actual.ip.address>.nip.io/api/
```

### Cleaning Up Kubernetes Resources

To delete the application deployment:

```bash
make k8s-delete K8S_INGRESS_IP=<your.actual.ip.address> # IP needed to identify manifest if it was generated
```

Or, to remove everything including the generated manifest, deployment, and cluster:

```bash
make clean-k8s K8S_INGRESS_IP=<your.actual.ip.address> # IP needed for manifest cleanup
```

_(Note: `K8S_INGRESS_IP` is needed for `k8s-delete` and `clean-k8s` if the `k8s-fast-demo.yaml` file was generated by `k8s-prepare-manifest` and you want to delete based on that specific file. If the file doesn't exist or IP is not critical for deletion logic, it might be omitted for some cleanup parts, but it's good practice to include it if it was used for deployment.)_

## Running with Docker (Local Development)

This section describes how to run the application using Docker directly for local development or testing, assisted by the `Makefile`.

### Prerequisites

- Docker installed on your system.
- Make installed.

### Build and Run the Docker Container

Use the Makefile target:

```bash
make docker-run-local
```

This command will:

- Build the Docker image `fast-demo:latest` (if not already built or outdated).
- Run the container in the foreground.
- Map port 8000 of the container to port 8000 on your host machine.

Alternatively, manual commands:

1.  **Build the Docker Image:**
    Navigate to the project's root directory and run:

    ```bash
    docker build -t fast-demo:latest .
    ```

2.  **Run the Docker Container:**
    Once the image is built:
    ```bash
    docker run -p 8000:8000 fast-demo:latest
    ```

### Accessing the Application (Local Docker)

When running directly with Docker, the application's `root_path` is `/api` (as defined in `main.py`). You can access the API endpoints:

Use the Makefile target to see the URLs:

```bash
make docker-access-local
```

Or access them directly:

- **Main API Docs**: `http://localhost:8000/api/docs`
- **Main API Root**: `http://localhost:8000/api/`
- **Main API Items (POST)**: `http://localhost:8000/api/items/`
- **Sub API v21 Docs**: `http://localhost:8000/api/v21/docs`
- **Sub API v21 Index**: `http://localhost:8000/api/v21/`
- **Sub API v21 Sub-route**: `http://localhost:8000/api/v21/sub`

Example using curl:

```bash
curl http://localhost:8000/api/

```
